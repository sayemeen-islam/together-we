## Commands

- `npm run dev` — dev server on http://localhost:3000.
- `npm run lint` — ESLint only; there is **no test, typecheck, or format script**. For type checking run `npm exec tsc --noEmit`, but note tsconfig includes types generated by Next (`.next/types`, `.next/dev/types`), so some route-typed props only resolve after a `dev`/`build` run has generated them.

## Tech stack quirks

- Next.js 16 App Router + React 19, code lives in `src/` (`src/app`, `src/components`). Path alias `@/*` → `src/*`.
- shadcn/ui configured with `style: "base-nova"` in `components.json` — components are built on **Base UI (`@base-ui/react`), NOT Radix**. Props and APIs differ from common shadcn/Radix snippets (e.g. no `asChild`). Add new components with `npx shadcn@latest add <component>`; don't hand-write Radix-based shadcn code from memory.
- Tailwind v4 with CSS-only config: design tokens and theme (`@theme inline`, CSS variables for `primary`, `muted`, etc.) live in `src/app/globals.css`. There is no `tailwind.config` file; `@tailwindcss/turbopack` is wired via `next.config.ts`.
- Use the `cn()` helper from `@/lib/utils` (re-exports the `cn` package) for conditional classes, not `clsx`/`tailwind-merge` directly.
- Icons: `lucide-react`.

## Environment Variables & Secrets Security

- Never read, print, expose, copy, or reveal the actual values of environment variables from `.env`, `.env.local`, `.env.production`, or any other secret/configuration files.
- Never include secret values in source code, comments, logs, terminal output, documentation, screenshots, or Git commits.
- Never hardcode API keys, database credentials, JWT secrets, authentication secrets, private tokens, or passwords.
- Access environment variables server-side via `process.env.VARIABLE_NAME`.
- Never use the `NEXT_PUBLIC_` prefix for private or sensitive values — Next.js exposes these variables to the browser. Use `NEXT_PUBLIC_` only for values intentionally safe to expose publicly.
- Ensure all `.env*` files containing secrets are excluded from Git tracking via `.gitignore`.
- Keep `.env.example` (or equivalent template) files safe: variable names and placeholder values only, never real credentials.
- Do not remove, overwrite, rename, or modify existing environment files or their values.
- Do not display environment-variable values when debugging; check only whether required variables exist, when necessary.
- If a task requires a secret, reference it by variable name without exposing its value.
- Never send secrets to external tools, AI services, APIs, or third-party services unless explicitly required and authorized.

Agent behavior rules:

- Before changes involving environment variables, inspect the relevant source-code references without opening or printing secret values.
- Preserve all existing environment configurations.
- If a secret is accidentally exposed, warn the user immediately and recommend rotating it.
- Prioritize security over convenience.
